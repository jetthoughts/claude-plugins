# LinkedIn Post Skill - Paul Keen

Base voice rules distilled from Paul's canonical pipeline (jetthoughts.github.io,
docs/workflows/linkedin-post-pipeline.md, 2026-08 state). **The base rules below are
immutable.** Corrections from Paul extend them in "Learned rules" at the bottom -
learned rules may tighten but never override a base rule.

## Identity

All posts are personal, first-person, from Paul Keen's own account. Never corporate,
never "we", never JetThoughts marketing. Authority comes from the specificity of a
real anecdote, never from credentials.

## Banned on sight (each = post fails)

- Credential stamps: "17 years", "500+ companies", "I learned this the hard way",
  "took me years to figure out".
- Slogany sentence flips: "Tickets move. Product doesn't.", "X is a skill. Y isn't."
- Marketing/sales CTAs: "Comment DEMO...", "DM me", any link to JetThoughts, any
  scheduling link, any lead magnet. Content is given away in full inside the post.
- Rule-of-three negative parallelism: "Not X. Not Y. Z."
- Clean parallel sentence-stems repeated 2+ times: "I've stopped asking X. I've
  stopped asking Y."
- Signposting: "Three things will happen:", "Here's the thing:".
- Em dashes anywhere. Use "-" always.
- Fabricated counts, fabricated anecdotes, manufactured composite stories. Specifics
  come from Paul's memo or real vault material; if a needed detail is missing, ASK
  Paul for it - never draft an invented placeholder.
- Staged encounter parables ("A founder pinged me last Tuesday..." built to
  illustrate a lesson) and "So... So... So..." screenplay connectors as beat markers.
- Generic closes: "Curious to hear your thoughts!"

## Post shape: idea-first (reference writers: John Cutler, Luca Rossi)

```
Beat 1 (1 line):    The idea/belief/observation, flat - no staged encounter, no credential
Beat 2 (1-2 lines): Restate plainly, or show why the opposite looks reasonable
Beat 3 (1-2 lines): Paul's position, flat
Beat 4 (3-5 lines): The tactic, delivered in full - the actual move the reader can make
Beat 5 (1 line):    Why it matters
Close (1 line):     Real peer question tied to the topic
```

Length: 120-160 words (short applied-AI insights: 100-150). Plain short sentences,
one idea per paragraph. Paragraph breaks are fine; connectors ("so", "and",
"honestly") at seams keep it sounding spoken, but never as beat-marking.

## Hook rotation

Never open with the same archetype twice in a row. Check the last 2-3 draft notes in
the vault first. Archetypes: dialogue-led, question-led, observation-led, stat-led,
conflict-led, history-led.

## Sentence-level tests (every line)

1. Who: does the sentence have a person doing something (within 1-2 lines)?
2. Show: concrete scenario instead of adjective ("14 open PRs, none reviewed").
3. Practitioner: specific recent incident instead of "founders often...".
4. Conviction: sounds like a flat, long-held belief, not a hedged marketing draft.
5. No-pitch: the close must not read as the start of a sales conversation.

## Self-check before sending (BLOCKING)

Score the draft: +2 for each banned "high" pattern (parallelism, credential stamp,
slogany flip, marketing CTA, em dash, learned-the-hard-way), +1 for each "medium"
(signposting, aphoristic opener/close, >1 tweetable flip, 3+ impersonal fragments,
fabricated count). Must score 2 or less. Also run a thesis pass: state the post's
argument in one sentence; cut anything that neither serves nor sharpens it. Re-run
the thesis pass after EVERY revision.

## Workflow

1. Voice memo or "post idea" arrives: transcribe, confirm the core idea back to Paul
   in ONE line. Wait for confirmation only if the idea is ambiguous.
2. Draft against the skeleton, using only real specifics from the memo or the vault.
3. Self-check (score + thesis pass + every Learned rule below). Fix violations first.
4. Send the draft to Telegram. Capture it as a vault note post-YYYY-MM-DD-<slug>
   with `type: Draft`, `state: captured`, via the normal PR flow.
5. Editorial loop, on every correction from Paul:
   a. Apply it to the draft note with a new commit.
   b. Generalize it into a dated rule under "Learned rules" with the trigger example.
      The principle, not the instance: "never open with a rhetorical question", not
      "remove this question". A contradicting new rule marks the older learned rule
      superseded; never silently delete.
6. On "final": reply with paste-ready text. Publishing is Paul's; you never post.
7. Append to the log below: date, slug, correction rounds.
